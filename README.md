# Repro for callstack/react-native-brownfield#492

The `ReactNativeHostManager.kt` generated by `npm create @callstack/react-native-brownfield@latest` for a React Native CLI (non-Expo) project crashes the host app on the first `ReactNativeHostManager.initialize(...)`:

```
java.lang.RuntimeException: Feature flags cannot be overridden more than once
```

| Branch | `RnApp/android/brownfieldlib/.../ReactNativeHostManager.kt` | Result |
|---|---|---|
| `main` | as generated by the scaffold | crashes: `Feature flags cannot be overridden more than once` ([videos/crash.mp4](videos/crash.mp4)) |
| `issue-fix` | `loadReactNative(application)` removed, nothing else | crashes: `SoLoader.init() not yet called` |
| `working-fix` | `loadReactNative` removed and the `ReactHost` passed as a factory | starts and renders the RN screen ([videos/fixed.mp4](videos/fixed.mp4)) |

Each fix branch is one commit on top of `main`. The working change is also in [`fix-factory.diff`](fix-factory.diff).

## Steps

Requirements: Node 22+, JDK 17, Android SDK (`ANDROID_HOME`), and a running emulator or device (arm64).

```bash
git clone https://github.com/gronxb/react-native-brownfield-492-repro
cd react-native-brownfield-492-repro/RnApp
npm ci
npm run package:android          # brownfield package:android (Release AAR)
npx brownfield publish:android   # -> ~/.m2: com.rnapp:brownfieldlib:0.0.1-SNAPSHOT

cd ../HostApp
./gradlew :app:assembleRelease
adb install -r app/build/outputs/apk/release/app-release.apk
adb shell am start -n com.example.host/.MainActivity
adb logcat -b crash
```

Expected on `main`: the app crashes at launch ("Host492 keeps stopping") with the trace below.

To try a fix, run `git checkout working-fix` (or `issue-fix`) and repeat from `npm run package:android`. Build HostApp with `./gradlew :app:assembleRelease --refresh-dependencies` so it picks up the republished SNAPSHOT.

## Cause

1. The template calls `loadReactNative(application)`. That runs `SoLoader.init`, then `DefaultNewArchitectureEntryPoint.load()`, which calls `ReactNativeFeatureFlags.override(...)`.
2. It then calls `ReactNativeBrownfield.initialize(application, reactHost, ...)`, which runs `loadNativeLibs`, which runs `SoLoader.init` and `load()` again. The library's `nativeLibsLoaded` guard is private and cannot see the earlier `loadReactNative` call.
3. `ReactNativeFeatureFlagsAccessor::override` throws on the second call. It has no idempotence guard in RN 0.85.2, or in 0.87.1 (the latest release).

Removing only `loadReactNative` (`issue-fix`) is not enough. The template passes `val reactHost by lazy { getDefaultReactHost(...) }` to the deprecated `initialize(application, reactHost, ...)` overload, so the host is built at the call site, before `loadNativeLibs`. `getDefaultReactHost` loads `JSRuntimeFactory`, whose static initializer calls `SoLoader.loadLibrary` before `SoLoader.init`. The `@Deprecated` message on that overload describes this case.

The working fix passes the host through the factory overload, as the Expo template (`ReactNativeHostManager.post55.kt`) already does:

```kotlin
ReactNativeBrownfield.initialize(application, onJSBundleLoaded) {
    getDefaultReactHost(
        context = application,
        packageList = PackageList(application).packages,
        jsMainModulePath = "index",
        jsBundleAssetPath = "index.android.bundle",
        jsBundleFilePath = null,
        useDevSupport = BuildConfig.DEBUG,
        jsRuntimeFactory = null
    )
}
```

Caveat: `loadReactNative` also calls `WindowUtilKt.setEdgeToEdgeFeatureFlagOn()` when `IS_EDGE_TO_EDGE_ENABLED` is true, and `ReactNativeBrownfield.loadNativeLibsInternal` does not. This repro uses `edgeToEdgeEnabled=false`. A template fix should keep that call, in the template or in the library.

## Unrelated issues you may hit (not #492)

- **Scaffold fails under `npm create`.** In 5.3.0, `npm create @callstack/react-native-brownfield@latest` fails with `Cannot find module '@babel/runtime/helpers/interopRequireDefault'`, because `@babel/runtime` is not a declared dependency. Workaround: in a separate directory, run `npm i @callstack/create-react-native-brownfield@5.3.0 @babel/runtime`, then `node_modules/.bin/create-react-native-brownfield --path <RnApp>`. This repo already contains the scaffold output, so you don't need to run it.
- **Published POM needs an unpublished artifact.** The generated `brownfieldlib/build.gradle.kts` declares `api("com.facebook.react:hermes-android:0.85.2")`, which is not published. Inside the RN project the RN Gradle plugin substitutes `com.facebook.hermes:hermes-android:250829098.0.10`, but the published POM keeps the original coordinate, so a plain host app fails to resolve it. `HostApp/app/build.gradle.kts` has a `dependencySubstitution` for this.
- **Absolute path in the Xcode project.** The scaffold writes the `BrownfieldLib` group in `RnApp/ios/RnApp.xcodeproj/project.pbxproj` with the absolute path of the machine it ran on. iOS is not part of this repro.
